# 从Basic Auth迁移到JWT

> 本文档说明如何将 FlowerUI 从 HTTP Basic Auth 迁移到 JWT Bearer 认证。

## 背景

v0.9.0 对鉴权系统进行了重构，核心变更：
- `/api/auth/login` 返回 JWT Bearer token
- `get_current_user()` 仅校验 `Authorization: Bearer <token>`
- `Authorization: Basic ...` 请求头不再支持（除非开启过渡兼容模式）

## 迁移步骤

### 步骤1：确认无内部工具依赖Basic Auth header

检查你的内部脚本、监控工具、CI/CD流程等是否直接使用：

```
# 旧方式（已失效）
curl -u username:password http://localhost:5555/api/workers
# 或
curl -H "Authorization: Basic dXNlcjpwYXNz" http://localhost:5555/api/workers
```

如有此类调用，需要在步骤2中统一替换。

### 步骤2：更新客户端代码，改用/login接口获取token

```
# 新方式：先登录获取 token
LOGIN_RESPONSE=$(curl -s -X POST http://localhost:5555/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"your-password"}')

# 提取 token（需要 jq）
TOKEN=$(echo "$LOGIN_RESPONSE" | jq -r '.access_token')

# 后续请求使用 Bearer token
curl -H "Authorization: Bearer $TOKEN" http://localhost:5555/api/workers
```

### 步骤3：将Authorization: Basic ...替换为Authorization: Bearer <token>

| 场景 | 旧写法 | 新写法 |
|------|--------|--------|
| curl命令 | `-H "Authorization: Basic dXNlcjpwYXNz"` | 先login获取token，再 `-H "Authorization: Bearer <token>"` |
| Python requests | `auth=('user', 'pass')` | 先login获取token，再 `headers={'Authorization': f'Bearer {token}'}` |
| JavaScript fetch | `headers: { 'Authorization': 'Basic dXNlcjpwYXNz' }` | 先login获取token，再 `headers: { 'Authorization': `Bearer ${token}` }` |

## 过渡期兼容模式

如需保留Basic Auth兼容，设置以下环境变量：

```
# 开启过渡兼容模式（默认关闭）
legacy_basic_auth_enabled=True
```

或在运行时配置界面中设置 `legacy_basic_auth_enabled` 为 `true`。

> **注意**：过渡模式将在 2 周后移除，请在此之前完成迁移。

## Token刷新与过期

- JWT token 默认有效期由 `FLOWER_TOKEN_EXPIRE_MINUTES` 控制（默认 30 分钟）
- 修改密码后，所有旧 token 自动失效（token_version + 1）
- 建议前端实现 token 自动刷新机制

## 常见问题

### Q: 我的监控工具依赖Basic Auth怎么办？
A: 在过渡期内保持 `legacy_basic_auth_enabled=True`，同时规划迁移到JWT。

### Q: 如何批量刷新所有用户的token？
A: 修改任意用户的密码会触发 `token_version + 1`，使所有旧token失效。

### Q: 匿名访问还支持吗？
A: 当 `auth_enabled=False` 时，所有接口免鉴权访问，返回 `anonymous` 用户。
