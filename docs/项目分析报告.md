**一句话总结**：功能面与 Flower 2.0.1 的"全量对齐"声明基本属实（已对照参考源码逐项核实），工程质量在重构类项目中属中上；但存在 **1 个阻断官方 Docker 部署的致命 bug、一组安全配置隐患、前端定时器泄漏、图表主题断链**，以及作为"生产监控平台"最缺的**告警/历史/权限/审计**四块能力。

## 二、Bug 审计核心结论（详见 bug-analysis.md）

### P0 致命（1）
- **P0-1 Docker 部署下前端完全不可用**：`Dockerfile:47` 产物在 `/app/static`，`main.py:37-42` 却按 `parents[2]/frontend/dist` 查找且未设 `FLOWER_FRONTEND_DIST` → 容器内所有页面路由 404。修复只需 Dockerfile 加一行 `ENV FLOWER_FRONTEND_DIST=/app/static`（或改 COPY 目标路径），建议加构建自检。

### P1 严重（8）
| 编号 | 问题 | 位置 |
| --- | --- | --- |
| P1-1 | CORS 默认 `["*"]` + `allow_credentials=True`，实测回显任意 Origin 带凭据 | main.py:90-96 |
| P1-2 | `basic_auth` 为空但开启认证时存在 **admin:admin 后门** | security.py:50-51 |
| P1-3 | `GET /api/config` 向任意登录用户（认证关闭时匿名）**明文返回全部用户凭据** | runtime_config.py:264-266 |
| P1-4 | 每次认证把**明文凭据列表写入日志** | security.py:45-46 |
| P1-5 | `/api/task/apply` 无限等待可**耗尽共享线程池**（DoS，控制面瘫痪） | tasks.py:189-206 |
| P1-6 | Dashboard/Monitor 页 15s 定时器**永不清理、每次进入累加**（UI 报告 D1/M1 同项） | DashboardView.vue:123 / MonitorView.vue:120 |
| P1-7 | `manage.sh stop` 会**杀死本机全部 python/node 进程** | manage.sh |
| P1-8 | RabbitMQ 非默认 vhost 时请求**错误的 Management API** | broker.py |

P2 共 18 项（含：WS 模式下 Worker 表格不实时、`/api/system` 未鉴权、登录无速率限制、每次 broker 查询新建不关闭的 Redis 连接池、mock 与真实模式 idle_since 类型不一致、url_prefix 不生效等），P3 共 21 项，全部带定位与修复代码，见报告原文。

> 质量说明：CORS 回显、celery 异常类型、urljoin 行为等关键结论均在项目 venv（Python 3.13 / celery 5.6.3 / fastapi 0.141.1）实测；10 个被排除的误报候选记录在附录 B。

## 三、页面/UI 核心结论（详见 ui-improvements.md）

52 个优化点（高 12 / 中 22 / 低 18），**每个均引用具体文件行号与代码**。Top 5 高优先级：

| # | 优化点 | 说明 |
| --- | --- | --- |
| G1 | **图表主题断链** | 主题已定义 `--fu-chart-*` 令牌但 `useChart.js` 未消费，40+ 处硬编码浅色 hex → 暗色/自定义主题下所有 ECharts 轴线和图例不可读 |
| G2 | **2s notMerge 全量重绘** | 抹掉用户图例选择等交互；全站 8 个图表无 dataZoom |
| D1/M1 | **15s 定时器泄漏** | 离开页面后持续发请求（与 bug P1-6 同源） |
| T2/T1 | **keep-alive 下 5s 轮询永不取消** + 任务列表撤销/终止按钮与详情页 disabled 逻辑不一致 | 离页后台空转、回页数据陈旧 |
| G3 | **错误 toast 双弹** | axios 拦截器与视图 catch 各弹一次 |

其余高优：G4 表格密度设置项是断头功能（从未生效）、G5 配置页未保存无离开保护、G7/LAY1 移动端无断点（侧边栏恒 216px、抽屉固定宽度溢出）、C1 配置页无搜索框。报告还列了 12 个"做得好的地方"建议保持，并按三批给出实施路线图。

## 六、风险与建议

1. **最优先**：P0-1（Docker）是"官方部署路径不可用"，一行修复，立即做。
2. **安全**：P1 四连修完后，生产部署务必显式配置 `FLOWER_CORS_ORIGINS` 白名单与强凭据；`/api/config` 的凭据明文返回建议与 RBAC（F P0-3）合并设计。
3. **前端生命周期**：定时器/轮询泄漏在 bug 与 UI 报告中共现 3 处（D1/M1/T2），建议统一封装 `usePolling` composable（处理 onUnmounted + keep-alive activated/deactivated + 后台标签页暂停），一次性根治。
4. **主题系统**：令牌体系是完备的，断点只在图表层（G1），修复成本低、收益覆盖 14 个自定义主题，性价比高。
5. **防回归**：第一阶段所有修复建议同步补最小单测/接口测试（F P2-4 的 pytest 基建 0.5 天即可先做），避免"修了再坏"。
